Atlas security review

We checked every Atlas server from the outside, reviewed the identity engine's code, scanned the full history of our source code for leaked secrets, and proved account isolation on the live network. This is everything we found and what we did about it.

Summary
  • Six servers checked on every port, over IPv4 and IPv6. From the internet, each now answers only on secure web.
  • Account isolation proven live: two test accounts on the real network could not reach each other, our servers, or a real subscriber's device.
  • Code review of the identity engine found four issues (one high, two medium, one low). All four were fixed, tested and live the same morning, plus one small follow-up the same day.
  • Two server weaknesses found (password login allowed, software versions visible). Both fixed the same night.
  • No secrets in 1,739 commits of source-code history.
  • Nothing found was ever used against us. The server logs show no successful break-in.

What we found and fixed

SeverityWhat we foundWhat we didStatus
High When setting up home access for an edge unit, the identity engine accepted any network range, not just a home one. An account could have named a range belonging to Atlas or to someone else. Only private home-sized ranges are accepted now. Atlas's own ranges are refused, one account per range, and only for an account that has its own edge unit. 31 new tests. Fixed, live 5 Oct
Medium A change to the private network's access rules was checked against the old rules, not the new ones, before going live. The new rules are now checked before they replace the live ones. A failed check changes nothing. Fixed, live 5 Oct
Medium Removing an edge or home device from an account left it on the private network. Removing a device now removes it from the network too. Fixed, live 5 Oct
Low A per-account limit could be slightly exceeded by many requests sent at the same moment. The limit is now reserved in one step. A test with 40 simultaneous requests stops exactly at the limit. Fixed, live 5 Oct
Low Follow-up from the high finding: one rare address format passed the new check but couldn't be used by the network. That format is now refused with a plain message. Test added. Fixed, live 5 Oct
Medium Administrator login accepted passwords on five of six servers, so anyone could keep guessing. The control server logged 15,391 failed attempts, ordinary internet background noise. None succeeded. All six servers now accept only cryptographic keys, and new servers are built that way. Then we went further: administrator login is no longer reachable from the public internet at all, only through Atlas's own private network. Fixed 5 Oct
Low Servers named their software and versions in replies, and two services published a full map of their endpoints. Software labels removed on every server, API maps switched off, and standard security headers added to every Atlas web address. Fixed 4–5 Oct

Every fix was backed up before the change, verified on the live system after it, and recorded in our internal change log.

One historical item, for completeness: in September an Android signing key was found in an earlier public copy of the app. It was retired and replaced at the time, and every Android release since has been signed with a new key.

Isolation, proven on the live network

Separation between accounts is the core promise, so we tested it on the real network rather than on paper. We created two throwaway test accounts, each with its own server, set up exactly as a new subscriber's would be.

From a test account, trying to reach…Result
The other test accountBlocked
Atlas's control server and an exitBlocked
The administrator's computerBlocked
A real subscriber's edge unitBlocked

Each test account could see only itself. The administrator's own computer couldn't reach a subscriber's device either: Atlas staff have no path into customer devices. Afterwards the test accounts, their access groups and both test servers were deleted.

Protecting the source code

  • Two-factor sign-in is on for the code host account, and only the founder has access.
  • An encrypted offline copy of all source code and its history is kept, and a test restore succeeded.
  • The foundation code is tagged by date from the first app onward, as a record of authorship.
